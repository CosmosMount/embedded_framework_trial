# 文档分层与使用说明

本包是组织模板，不是项目审查结果；没有修改用户本机配置或运行项目测试。占位字段不构成事实或授权。工具入口说明沿用文末资料，本次修订未重新核查运行器版本；改进验收、退役和清理条款是工程约定，不是运行器内置功能。

## 1. 只引入需要的文档

`global/AGENTS.md` 保存通用工程偏好，`project/AGENTS.md` 是项目工作入口，SPEC 保存需求与验收。DESIGN 仅在需要长期设计说明时启用，示例计划仅用于复杂任务，本说明无需复制到项目。已有权威需求、设计或测试时直接使用原文件并调整入口，不为模板另建一套。

通用规则管怎样工作，需求管必须实现什么，设计管已采纳的实现方式，计划管当前任务。测试是可复用资产，不是逐轮产物；同一行为优先扩展已有测试。简单任务可以只有代码、必要回归测试和交付回复，不生成计划、报告或日志目录。

## 2. 放置与合并

Codex 用户级指导默认位于 `~/.codex/AGENTS.md`；设置了 `CODEX_HOME` 时以其为准。[1] 将 global 文件与现有规则比较合并，不直接覆盖。Windows、WSL、远程或容器分别核实实际用户与目录。将 project 入口及所需模板引入仓库，保留既有项目约束、命令和用户修改；无需引入未使用的 DESIGN、示例计划和 SETUP。

项目必须保证的根因修复、改进验收、旧实现退役和产物边界在项目入口保留，不只依赖个人全局规则；完整个人风格不必复制成第二套仓库规范。合并本次条款时替换旧的对应表述，不在文件末尾另加一套冲突规则。

## 3. 运行器如何读取

Codex 在启动运行或 TUI 会话时建立指导链：先用户级，再沿项目根到当前工作目录；各层优先 `AGENTS.override.md`，再 `AGENTS.md`，项目层还有可配置的后备文件名，每个目录最多选一份。更深层指导用于局部覆盖，不代表已递归加载所有子目录。[1]

普通 Markdown 链接不会把任意文档自动加入指导链，因此项目入口必须写明何时实际读取 SPEC、DESIGN 或计划。更新指导后新开会话复核，不假定旧会话重载。上述机制针对 Codex，其他工具按自身说明配置。[1]

在只读环境中，可要求 Agent 列出已加载指导与实际读取的项目文档，区分“已读取”和“仅看到引用”，说明工作边界和真实验证入口。复述不是合规证明，仍须检查实际代码、diff 与验证结果。AGENTS 是指导；技术权限由 sandbox 和审批等机制控制，不是 Markdown 提供的隔离。[2]

## 4. 按收益保留，按条件退役，按节点清理

修改前在已有任务记录或回复说明有效基线、预期收益、受保护行为和可接受代价。相对任务开始前比较，不拿前轮造成的退化作基线。收益可为正确性、新能力、可靠性、性能或结构简化，不要求所有维度提升；无收益或不可接受退化的方案应重构或撤除，不因工时或代码量保留。未验证只能称收益未知，不是通过，也不是已证实无收益。

每轮审查源码与累计改动，允许必要局部重构，重复失败先复审原因。新方案已通过验收且迁移完成后，默认清除本次替代范围内无用途的旧实现及专属附属项，保留有效行为和回归测试。真实兼容或回滚义务才支持过渡路径，并在现有文档写明退出条件，不永久双轨。撤除不能回退用户修改或盲目恢复已知错误状态。

简单任务直接回复，复杂任务只更新一个计划。确需原始诊断才创建 `.agents/runs/<task-id>/`；先限制采集范围和规模，默认不保存完整成功输出。方案被淘汰或合并时清理无用尝试；问题与回归验收闭合后清理不再承担诊断或留存责任的旧输出；替代及迁移完成后退役旧路径；交付或交接前复审残留。按状态和用途清理，不按日期批量删除，也不把所有历史永久归档。

闭合失败的冗余原始记录可删除，但有意义的失败结论在原计划或交付内保留；未决唯一证据、持久测试、正式实验数据、必留审计及安全日志不能按临时文件处理。清理保护用户和其他任务修改及归属不明内容，不扩大到工具日志或全仓。

这些约定不要求新建收益评分系统、审计脚本、日志框架、清理服务、Git hooks 或额外报告。现有入口能验证就复用，历史使用既有版本管理，不擅自提交、重写历史或逐轮制造源码副本与 ZIP。文档更新原位替换；仅在需要交付模板包时生成一个当前包，不把打包作为代码任务默认步骤。
