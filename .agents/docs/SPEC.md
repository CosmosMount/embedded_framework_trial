# PnX 项目需求与验收

适用仓库：Penix。本文维护项目约束与验收；实现机制见 [DESIGN](DESIGN.md)，执行证据见任务计划。源码现状不等于已验证能力。

## 目标与范围

项目提供 STM32 + ThreadX 机器人固件基础架构：板级资源、配置生成、BSP、设备驱动、功能模块、通用库与应用入口。两板启动钩子已进入 `app_start()`，当前仅初始化基础日志，具体机器人业务尚未实现。

配置集中到 configs，解析不依赖 boards。IOC、固定绑定、板型身份、参数、设备组合、preset、工具链和产品链接脚本由 configs 管理；boards 保留 CubeMX 生成产物。根 CMakePresets.json 仅作为工具发现入口。自有代码整理保留有效公开能力、资源边界和已确认的设备行为，不批量重排生成代码与第三方实现。

## 工程约束

- 根 `CMakeLists.txt` 定义 C11、C++17、源码选择与 BSP 板族校验；保留有效公开接口和 ThreadX/HAL 回调。
- 配置参数以现有 JSON 为准；生成文件仅写入构建目录，不手工维护第二份配置。
- `PNX_BOARD` 自动选择 `bsp/<板型>/`；`PNX_BSP_SOURCE_DIR` 默认留空，仅显式指定含 target.cmake 的替代板型目录，仍须通过板族校验。
- 根固件构建可消费 boards 产物，但独立配置生成与编辑器导出不得读取其中的 PnX 配置。整理代码不改变硬件参数；硬件配置变更须有明确需求并通过 IOC 重生成核验。
- 不编造性能、内存和时序阈值，不将编译通过等同于硬件验证通过。

工作目录为仓库根目录；构建需要 CMake 3.23 或更高版本、Ninja 和 Arm GNU Toolchain。

| `git diff --check` | 受跟踪修改无空白错误，不替代行为测试 |
| 目标硬件检查 | 操作者明确执行，具体接线、业务指标与步骤尚未定义 |

## 分层、单位与调度

- 按 boards、bsp、devices、modules、app/controllers 划分职责和依赖方向，不强制每次调用经过所有层。允许省略无职责的中间层，但不得绕过已有设备的协议、单位和校验接口；上层不得访问 HAL、寄存器或 BSP 私有实现。具体允许依赖见 DESIGN。libs 可跨层复用且不依赖硬件；设备不拥有线程。
- 物理量采用 rad、rad/s、Nm 和右手系；未知电机换算参数等待可核验手册，不伪报已支持 Nm。可变项沿用 configs JSON，控制调参使用明确全局实体。
- 温控与采样必须保持独立执行和可独立设置的频率，以有界互斥保护共享事务，状态按一致快照交接。验收须覆盖锁超时、传输失败释放、配置延时不持锁；硬件测量另核验采样抖动和温控周期。

## 嵌入式类型与空间约束

适用自有固件源码（app、modules、devices、bsp、libs）和 configs 生成的 C/C++；不修改 CubeMX、HAL、ThreadX、CMSIS 等第三方定义来迁就风格。主机测试工具不计入固件空间预算。

- 根据语义范围和正负选择类型：字节、8 位标识与有界小索引用 uint8_t；需要超过 255 的长度或计数用 uint16_t；时间戳、持续累计计数、硬件寄存器使用所需的 uint32_t；确实需要长时间线或大范围累计时保留 uint64_t。允许负数、误差或负哨兵时使用适当的 int8_t/int16_t/int32_t 或 int，不能因追求小类型破坏负数语义。
- 固定宽度类型直接写 uint8_t、uint16_t、uint32_t、int32_t 等，由 <stdint.h> 提供，不加 std::。地址用 uintptr_t；仅用于 sizeof、内存跨度和库接口等真实尺寸语义时保留 size_t，由 <stddef.h> 提供。禁止把所有索引、协议长度和业务计数统一写成 size_t，也禁止把任意输入未经校验截断成小类型。
- 自有固件不使用 std::array、std::vector 或其他容器式数据存储。采用元素类型明确、容量编译期确定的原生数组 T buffer[N]，长度、有效元素数和所有权显式表达。允许具有对齐、DMA 所有权等实际职责且内部使用固定原生数组的资源类型，不另造通用容器替代 STL。空资源表不产生非标准的零长度数组。
- 容量须来自协议、配置或已知资源上限，计数类型必须同时容纳有效范围、满容量和哨兵值。生成器拒绝超出表示范围的配置；循环终值、加减乘法、整数提升、符号比较、回绕及窄化转换都须核对。协议对象不能用更小的宿主类型破坏线格式。
- 空间优化以对象大小、对齐、缓冲容量、链接结果和必要运行测量为依据。不默认 std::array 比同类型原生数组更大，也不因去掉 std:: 前缀宣称节省 RAM。小整数不必然缩小对齐后的结构或生成指令；不为节省字节使用不安全 packed、不必要位域、过小栈或会溢出的累计器。

## 封装有效性与结构轻量化

封装必须承担可说明的职责：协议与单位转换、资源所有权与生命周期、并发保护、硬件差异隔离，或被实际调用方复用的计算。仅改名、原样转发、重复保存下层状态、为假想后端引入注册表/虚接口，不能作为新建层、类或目录的依据。允许直接调用稳定的下层公开接口；不因函数短就删除必要的边界、校验和语义。

复审时沿真实调用链检查，包括生成绑定、回调和外部入口。删除无职责中间层时同步迁移调用、错误语义和有效测试，移除专属注册、配置与旧文件，不保留空壳兼容层。测试替身的便利不能单独证明生产抽象必要；也不为减少文件数合并独立职责。公共能力不因暂时没有仓内调用就自动视为幽灵函数。

同一计算或协议能力只维护一份负责实现，实际消费者复用；归属按语义、依赖和所有权决定，不在设备或模块内再造通用数学、校验或控制库。协议头只维护线格式、协议标识与容量契约，接收队列、线程状态和解析流程归其所有者。相似代码须先核对单位、坐标、错误语义、并发与算法差异；不同 CRC 多项式、滤波响应和板级硬件实现不能仅凭外形相似合并。

源码逐字相同只证明当前实现重复，不证明不同协议或硬件模式的完整契约相同。合并前还须检查是否两条路径都遗漏必要行为；例如 Classic CAN 与 CAN FD 的数据相位、BRS、接收 FIFO 和发送延迟补偿按实际配置保留差异，共享初始化步骤不能抹掉模式专属能力。

自有接口不得存在“幽灵函数”：已声明的非抽象能力必须有真实实现，并在支持该能力的构建配置中接入；不得用未实现声明、空函数或固定成功返回冒充功能。复审逐项核对声明与定义、内联/模板、生成源码、外部提供者、纯虚接口的具体实现及条件选源，不能只依赖默认产品链接通过（未被引用的声明不会触发链接错误）。确认废弃且无支持义务的入口应删除其声明、配置、文档与专属依赖；仍需支持的能力须补齐实现与真实路径验证。框架回调、实际由生成器或外部组件提供的符号，以及无仓内调用但已完整实现的公开能力，不属于幽灵函数。

编译期已确定的设备选择优先直接装配具体类型；无运行期替换需求时，不再叠加 void*、函数指针或工厂转发。跨层同名组件须核对职责与数据流，设备实现使用协议/型号名，执行模块使用实际职责名；不能只改文件名而保留无意义中间接口。

线程入口直接表达该线程独占的工作流程。私有函数只有一个调用点、仅拆出一次轮询或线程循环体，且没有独立的协议、算法、资源生命周期或并发职责时，应并入线程入口，不保留“薄线程 + 单次工作函数”。循环中的多次执行不等于多个调用方，测试调用也不构成生产复用。复审须检查真实调用、回调注册和配置选源；保留承担独立职责或实际复用的函数，以及框架要求的入口签名，不以调用次数机械内联复杂算法或资源清理。

绑定只在需要解释配置角色、装配具体设备、连接逻辑资源与私有硬件，或适配真实回调签名时保留。单个实现可直接完成的局部装配应归其所有者，不为每层单独生成 binding 文件、注册表或转发对象。退役绑定时同步移除生成入口和消费者；BSP 私有 HAL/DMA 映射不得泄漏到上层，公开配置别名不因当前产品未使用就直接删除。

## 命名、文件组织与防御性检查

- 名称结合命名空间与类表达具体职责：类内 on_rx/thread_entry 不重复型号前缀，sample 表示读数，state 表示发布状态。避免靠 service/manager/helper 或 raw/data/info 近义词区分职责，保留型号、单位、协议与状态阶段，不追求最短缩写。不批量改写第三方、协议规范或固定 ABI 名称。
- 对近义接口核对真实调用链；同义入口合并，语义不同则明确区别。重命名同步更新构建、生成代码、配置引用和测试，不遗留无人使用的兼容别名。
- 文件数与体积一起评审，不设固定行数配额。紧密相关的细碎声明或少量纯函数可集中；公共头只放使用者需要的内容，私有线格式与算法就近放入实现。大文件先消除重复，再按独立职责拆分，不逐函数拆文件，也不为压文件数制造巨型文件。
- 防御检查对应真实边界：外部报文、公共输入、硬件失败、资源竞争和跨上下文必须校验。删除分支前证明条件由类型、初始化或调用方保证；不能把异步变化当作不变量。私有契约不重复兜底、不静默换对象、不伪造成功，保留缓冲边界和失败清理。
- 扫描、调用链复核、构建、行为回归与硬件实测分别陈述。不以文件数或行数减少宣称全面优化，不因公共能力暂无仓内调用就认定可删除。

公共归属按语义决定，不能仅因多个层引用就放进 libs/common。同一设备族共享的类型与协议归设备族接口；板级内存布局、DMA 放置规则归 BSP；模块只追加调度、来源与发布状态。只有不包含设备/业务/板型知识的共享能力才归通用库。整理时优先并入已有职责明确的接口，避免为了移动类型另造 common/types/helper 文件；迁移后删除旧头和别名，并核对生成配置及所有消费者。

## 接口与时序约束

- 依赖遵循“分层、单位与调度”及 [DESIGN 的职责与依赖](DESIGN.md#职责与依赖)，禁止反向业务依赖和循环依赖。
- 同周期一致性的验收对象是输入版本：周期所有者先捕获数据及序号/时间，再向所有控制器传递同一个 const 输入集合。本周期不得各自重新读取 latest；控制计算阶段不持外设锁。RTOS 允许抢占，要求锁等待、持有时间和截止时间有界并可测，不能承诺零抢占或零抖动。
- 异步接收数据的新鲜度以接收时刻判断，排队、解码及重复发布不得刷新数据年龄。分帧读数须限制组装时间，完整快照使用能反映最旧有效组成部分的时间戳；过期工作状态不得与新帧拼接，序号不能因短暂失联而复用。校验与解码失败保留上一有效输出，并由消费者继续检查其年龄。
- latest 消息通道默认不等待锁；读写竞争返回 busy，失败不消费待处理状态或改写载荷。调用方显式处理跳过/沿用策略；阻塞发布必须显式启用，不作为控制周期的默认行为。
- 通用操作状态限定为 `ok`、`error`、`not_configured`、`invalid_arg`、`busy`、`not_initialized`、`timeout`。其中 `busy` 统一表示非阻塞调用当前无法取得资源或数据，`invalid_arg` 包含非法参数与非法调用上下文；协议或设备的专有状态由其自身类型表达，不继续扩张通用枚举。查询与纯计算直接返回值。不会失败的赋值、状态重置和纯副作用操作允许 void，不添加永远返回 `ok` 的分支。HAL/ThreadX 固定 void 回调必须保留框架签名，通过状态或计数报告失败，不增加永远返回 `ok` 的适配层。
- 日志只补充无法由调用者及时观察的故障和状态转换，不替代返回状态、设备快照或产品保护。记录必须定长、有界、无动态分配且不等待锁；高频采样和每周期成功路径不得写日志。日志满时覆盖最旧记录，不得阻塞控制周期。保留 RAM 日志只能声明跨软件/看门狗复位保留，不能声明断电保存；调试器下载、复位方式和启动代码是否清 RAM 仍须按工具链验证。
- 不把未在当前产品启用的驱动判定为幽灵；检查生成配置、公开接口、回调和可选构建后再退役。通用模板应以真实第二个实现共享语义，不能为未知硬件预置空基类。

同类设备的归属以职责决定，不以同步轮询或异步传输方式区分层级。遥控器的协议解码和设备读数统一归 devices/remotes；模块只负责调度、缓存交接、失联、事件及发布。设备不得依赖模块类型或创建线程；共享数据定义不得依赖具体硬件。

## 遥控输入选择

DR16 与 VT03 允许同时接收。VT03 在线且最后有效帧未超过配置期限时，优先使用其整套输入；失联后切换到仍有效的 DR16，VT03 恢复后自动切回。不得拼接不同来源的摇杆、开关与键鼠。两路均无有效输入时输出离线和归零状态。新鲜度依据帧接收时间，重复发布不能延长有效期；最终输出的按键边沿及前一状态以最终输出序列为准。

PS2 仅支持同步 GPIO/SPI，通过 gamepad 独立线程轮询，当前不自动映射为键鼠；串口 PS2 已退役，不保留接收器、解析器或配置入口。启用的接收器必须使用互不冲突的 UART；配置生成阶段拒绝已知冲突，不静默停用裁判或修改接线。验收覆盖优先选择、超时切换、恢复抢占、全部离线、旧快照重复发布和 tick 回绕。

## 当前基础框架范围

基础数学类型、角度换算和姿态转换统一归 `libs/math`；复用与接口完整性遵循“封装有效性与结构轻量化”。CMSIS-DSP 按实际使用的源码编译并链接；固定小尺寸内联运算与通用内核按运算特征选择，性能结论必须对应目标芯片、编译选项和可比测量，不能由库名推断。

自有固件数学运算通过返回值或状态表达异常，不依赖数学函数设置 errno；编译启用 `-fno-math-errno`，允许单精度平方根使用硬件指令，保留浮点精度与 NaN 语义，不启用 `-ffast-math`。近似倒平方根只有在明确误差预算及目标板收益验证后才可替换姿态归一化。

基础框架提供 PWM、CAN 收发和错误通知、设备错误状态、独立温控与采样，不包含 PWM failsafe 或 H7 CAN 诊断统计扩展。加热启动先写零占空比，温控正常运行时继续调节并在错误时请求停热；任务停顿、CPU 卡死或调试暂停后的硬件超时关断不在当前保证范围。IOC/CubeMX 既有定时器及 DMA 配置保留；回收外设资源须由 IOC 重新生成并核验。
